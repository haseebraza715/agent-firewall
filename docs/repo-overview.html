Agent Firewall

A dependency-free Python runtime guard that allows, blocks, or pauses AI-agent tool calls before execution.

Evidence-backedLocal-first HTMLSource inspected

The problem it solves

Agents can repeat calls, overspend, or perform irreversible actions. Agent Firewall inserts a framework-neutral enforcement point in front of tools and local MCP servers.

Current features

  • Ordered allow/block/approval rules with glob and exact argument matching
  • Per-run call, cost, per-tool, and identical-call caps
  • Sync/async wrappers and human approval callbacks
  • Thread-safe in-memory or persistent SQLite reservations
  • Argument-free, hashed, redacted, or opt-in full JSONL audits with fail-closed writes
  • CLI checks and complaint replay
  • Transparent newline-delimited JSON-RPC MCP stdio proxy
  • Loopback-only approval dashboard with token, CSP, and idempotent decisions

Main execution flow

  1. Wrap a Python callable or intercept an MCP tools/call message.
  2. Canonicalize the call and evaluate ordered policy rules.
  3. Reserve projected budget atomically; reject call, per-tool, repeated-call, or estimated-cost overflow.
  4. If approval is required, use a callback, terminal prompt, or SQLite-backed web queue; otherwise fail closed.
  5. Execute only allowed calls, persist usage, and append an audit event. MCP responses are forwarded unchanged except policy errors.

Major components

Policy

Loads and validates JSON rules, default decision, audit mode, and budgets.

Firewall

Check, call, async call, wrapping, approval, reservation, and audit orchestration.

McpStdioProxy

Intercepts tools/call while preserving other JSON-RPC traffic.

SQLiteStateStore

Persistent call, cost, per-tool, and fingerprint counters.

SQLiteApprovalQueue

Cross-process pending/approved/denied decisions.

Dashboard

Loopback HTTP summary, event list, approval API, and minimal browser UI.

JsonlAuditLog

Privacy-aware append-only event recording that fails closed.

Installation and run commands

Commands below are taken from the repository. Run them from the project root unless the first command changes directory.

python3 -m venv .venv
source .venv/bin/activate
python -m pip install .
agent-firewall check --policy examples/policy.json --tool email.send --arguments '{"to":"customer@example.com"}'
agent-firewall replay --policy examples/policy.json --scenarios examples/complaints.json
PYTHONPATH=src python -m unittest discover -s tests -v
Local verification. Ran the documented unittest suite: 65 tests passed; 7 dashboard tests could not bind a loopback socket because this sandbox denies socket binding. No assertion failure was observed outside that environment restriction.

Implemented, partial, and planned

implemented

MVP rule engine, budgets, sync/async wrappers, audits, complaint replay, MCP proxy, SQLite persistence, terminal/web approvals, and loopback dashboard.

partial

Cost enforcement trusts the caller's estimate; dashboard and persistence are local/single-host by design.

planned

README explicitly defers semantic prompt-injection detection and multi-host distributed budgets until a real threat model and usage data exist.

Known limitations and technical debt

  • This is an enforcement point, not an OS sandbox; tools still need least privilege and isolation.
  • No semantic prompt-injection screening is shipped despite the older plan mentioning it.
  • No distributed/multi-host budget coordination.
  • Provider costs are not calculated; supplied estimates are enforced.
  • Checked-in agent_firewall.egg-info is generated packaging output.
